# Phase-Specific Development Documents

Future phase specifications normally belong in this directory as `phaseNN_topic.md` (or `phaseNN_M_topic.md` when a minor phase is needed). Each document should be self-contained and link to, rather than duplicate, [`AGENTS.md`](../../../AGENTS.md) and the [reusable phase workflow](../codex_phase_workflow.md).

A phase specification should state its goal, verified starting context, in-scope and out-of-scope work, safety constraints, required inspection, acceptance criteria, verification, commit/PR expectations, and follow-up. Use repository-relative paths and avoid machine-specific data or task transcripts.

Historical documents need not be moved solely to fit this convention. For example, [Phase 17 existing-tool depth](../../phase17_existing_tool_depth.md) remains at its established path and is linked as historical context.
